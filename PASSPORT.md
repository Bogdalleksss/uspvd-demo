## 2. Архитектура

Кликабельный прототип — ОДИН интерактивный артборд-оболочка `Main.dc.html` (артборд 390×844 в Claude Design, в опубликованной версии — адаптивный, раздел 10; `is_interactive: true`). Оболочка хранит всё общее состояние `app`, знает текущий экран, показывает его и нижнюю панель. Каждый экран — отдельный файл-компонент, который оболочка монтирует через `<dc-import>` и передаёт ему два параметра: `app` (состояние, только чтение) и `act` (функции-действия).

- Если в проекте экраны подключаются другим механизмом, сохрани сам принцип: одна оболочка с общим состоянием, экраны получают `app` и `act`. Имена файлов, полей и действий не меняй.
- Экран НИКОГДА не хранит общее состояние у себя и не меняет `app` напрямую — только через `act`.
- Локальное состояние экрана (текущий слайд, набранные цифры кода, открыт ли лист/диалог, ошибки полей до отправки) — в самом экране.
- Переходы между экранами — только через `act`. Ссылки `<a href>` между артбордами — только S13 → S14 и S14 → Main.
- Каждый экран-файл можно открыть и отдельно. Чтобы он выглядел заполненным в одиночку, в `renderVals()` используется `this.props.app ?? DEMO`, где `DEMO` — копия нужных экрану полей из раздела 5, значения один в один. `act` в одиночном режиме — пустые функции.

## 4. Общие правила вёрстки

- Язык `ru` (`<html lang="ru">`), у каждого файла свой `<title>` = название экрана.
- Шрифт Open Sans и иконки Material Symbols Outlined (тонкие, вес 300) — только через `<link>` в `<helmet>`, одинаковые ссылки во ВСЕХ файлах:
  - `https://fonts.googleapis.com/css2?family=Open+Sans:wght@400;600;700&display=swap`
  - `https://fonts.googleapis.com/css2?family=Material+Symbols+Outlined:opsz,wght,FILL,GRAD@24,300,0..1,0&display=block`
  - Иконка: `<span class="material-symbols-outlined" aria-hidden="true" style="font-family:'Material Symbols Outlined'; font-size:22px; line-height:1; font-variation-settings:'wght' 300,'FILL' 0,'GRAD' 0,'opsz' 24;">chevron_left</span>`. Заполненный вариант (`'FILL' 1`) — только у активной вкладки и статусных иконок.
  - Разрешённые иконки: account_balance, add, call, campaign, check_circle, chevron_left, chevron_right, close, credit_card, delete, description, error, groups, help, home, info, lock, logout, menu, notifications, payments, receipt_long, search, share, shield, expand_more, text_increase, warning, water_drop. Других иконок и эмодзи нет; новая иконка = правка паспорта.
  - Старый набор Material Symbols Rounded и параметр `icon_names` не использовать.
- Крупный текст: оболочка ставит на контейнер экрана CSS-переменную `--uv-text-scale` (1 или 1.25). ВСЕ размеры шрифта во всех экранах пишутся как `calc(18px * var(--uv-text-scale, 1))`, межстрочный интервал — без единиц (например `1.44`).
- Настоящие элементы: `<button>`, `<input>` + `<label>`; у кнопок-иконок `aria-label`. Зона нажатия ≥ 48×48.
- Кнопки, поля, карточки, баннеры, метки, диалоги — по описаниям компонентов дизайн-системы (Button, TextField, OTPField, ReadingInput, AccountCard, StatusBanner, NotificationCard, ListRow, TabBar, TopBar, BarChart, Dialog).
- Стандартная обводка фокуса браузера (`outline`) не используется нигде: у полей ввода, выпадающих списков, ячеек кода и текстовых областей `outline: none`. Фокус поля показывается только рамкой по дизайн-системе: 2px primary + кольцо 4px primary-soft (`box-shadow`). У кнопок и ссылок обводка убрана при нажатии мышью и пальцем (`:focus:not(:focus-visible)`), а при переходе клавишей Tab показывается аккуратное кольцо `box-shadow: 0 0 0 3px primary-soft` вместо стандартного outline.
- Диалоги подтверждения в приложении (S13 «Выйти», «Удалить аккаунт» и любые будущие): затемнение на ВСЁ окно приложения, включая нижнюю панель (`position: fixed; inset: 0`, выше таббара, без вложенных затемнений); карточка по центру, ширина `calc(100% − 40px)`, `max-width: 340px`, radius-lg, отступы 24px; заголовок 20/26 600, текст 15/22 text-secondary; две кнопки высотой 48px в одну строку равной ширины — слева secondary «Отмена», справа danger с заливкой error («Выйти», «Удалить»); на ширине до 340px кнопки в столбец, danger сверху; закрытие по «Отмена», клику по затемнению и системному «Назад»; фон под диалогом не прокручивается.
- S01: колонка на всю высоту — вверху Logo; блок «иллюстрация + заголовок + текст» по центру свободного места; внизу закреплён блок «точки-индикаторы (24px над кнопкой) + кнопка + подпись "Демонстрационная версия"» с отступом снизу `max(24px, env(safe-area-inset-bottom))`.
- TopBar экранов с «Назад»: прозрачный, на фоне экрана, без белой плашки и тени; слева шеврон `chevron_left` + слово «Назад», вызывает `act.back()`. Заголовка в панели нет — заголовок экрана `h1` слева в контенте под панелью.
- Никаких выдуманных фактов о водоканале сверх раздела 5. Неизвестное — плейсхолдер в квадратных скобках, например `[Текст политики предоставит водоканал]`.

## 6. Действия `act`

| Действие | Что делает |
|---|---|
| `go(id)` | Положить текущий экран в `stack`, открыть `id` |
| `back()` | Открыть последний из `stack`; пустой — ничего |
| `tab(id)` | Очистить `stack`, открыть вкладку (`S05`, `S06`, `S09`, `S13`); для `S09` через вкладку «Платежи» — `historyTab = 'payments'` |
| `home()` | Очистить `stack`, открыть S05 |
| `setPhone(digits)` | Сохранить до 10 цифр |
| `codeOk()` | С S03 → S04 (S03 не остаётся в `stack`) |
| `linkAccount()` | Очистить `stack`, открыть S05 |
| `setMeterCount(1 или 2)` | `meterCount = n`, `meters` и `readingsHistory` — вариант для n из раздела 5 (значения показаний сброшены) |
| `setReading(meterId, number или null)` | Записать значение счётчика |
| `submitReadings()` | `readingsSent = true`, `readingsSentAt = 'Сегодня, 10:42'`, `receiptNo = '2026-09-0418'`, в `usage` для «сен» — `totalConsumption`, в начало `readingsHistory` — `{ month: 'Сентябрь 2026', date: '21.09.2026', values }` со значениями всех счётчиков. Очистить `stack`, открыть S08 |
| `setPayAmount(number)` / `setPayMethod('sbp' или 'card')` | Записать |
| `pay()` | `paid = true`, `debt = max(0, debt − payAmount)`, `lastPayment = { date: 'Сегодня, 10:45', amount, method: 'СБП' или 'Карта', receiptNo: 'Ч-000418' }`, добавить его в начало `payments`. Очистить `stack`, открыть S11 |
| `openHistory(tab)` | `historyTab = tab`, `go('S09')` |
| `setHistoryTab(tab)` | Переключить вкладку S09 |
| `markAllRead()` | Все уведомления прочитаны |
| `toggleLargeText()` | Переключить `largeText` |
| `logout()` | Сбросить `app` к DEMO, открыть S02 (это же — перезапуск демо) |
| `deleteAccount()` | Сбросить `app` к DEMO, открыть S01 |
| `money(n)` | `1248.6` → `1 248,60 ₽` (неразрывный пробел) |
| `reading(n)` | `131` → `00131` |

## 9. Панель водоканала: вход и роли (S14)

S14 — отдельный артборд со своим состоянием, оболочка Main его не касается. Внутри три раздела, переключение внутренним состоянием `view`: `login` → `overview` ↔ `team`.

### Состояние S14 (DEMO)

```js
{
  view: 'login',            // login | overview | team
  me: null,                 // после входа — объект сотрудника из staff
  email: '', password: '',
  staff: [
    { id: 'u1', name: 'Сергей Петрович Кравцов', email: 'director@uspvodokanal.ru', role: 'owner',      status: 'active' },
    { id: 'u2', name: 'Марина Игоревна Лозовая', email: 'dispatcher@uspvodokanal.ru', role: 'dispatcher', status: 'active' },
    { id: 'u3', name: 'Ольга Сергеевна Дьяченко', email: 'buh@uspvodokanal.ru',      role: 'accountant', status: 'active' },
    { id: 'u4', name: 'Андрей Викторович Шульга', email: 'shulga@uspvodokanal.ru',   role: 'dispatcher', status: 'invited' }
  ],
  invite: { name: '', email: '', role: 'dispatcher' },
  banner: null              // локальные сообщения «Приглашение отправлено (демо)» и т. п.
}
```

Имена, адреса почты и роли — вымышленные демо-данные.

### Роли и права

| Роль | Ключ | Сводка и показания | Публикация уведомлений | Платежи | Сотрудники |
|---|---|---|---|---|---|
| Владелец | `owner` | да | да | да | **да, единственный** |
| Диспетчер | `dispatcher` | да | да | нет | нет |
| Бухгалтер | `accountant` | да | нет | да | нет |

Ролей ровно три. Других ролей в списках нет.

Правила:
- Раздел «Сотрудники», приглашение, смена роли и отключение доступа доступны ТОЛЬКО роли `owner`. У остальных вкладки «Сотрудники» нет вовсе.
- Панель разворачивается отдельно от мобильного приложения, поэтому ссылки «Вернуться в приложение» в ней нет.
- Владелец не может снять роль владельца с самого себя и не может отключить свой доступ.
- Блоки, недоступные роли, не показываются вовсе (а не показываются серыми): у диспетчера нет карточки «Оплачено», у бухгалтера нет формы публикации.
- Роль текущего сотрудника видна в шапке рядом с его именем.

### Экран входа (`view: 'login'`)

- По центру карточка: Logo, заголовок «Панель водоканала», поля «Рабочая почта» и «Пароль», primary «Войти».
- Демо-логика: если почта совпадает с одним из `staff` со статусом `active` — вход под этим сотрудником, любой непустой пароль подходит. Иначе ошибка «Сотрудник с такой почтой не найден».
- Под формой метка «Демо-режим»: перечень почт для входа (владелец и диспетчер) — чтобы на показе можно было войти разными ролями.
- Ссылка «Забыли пароль?» показывает баннер «В демо-версии недоступно».
- Выход — компактная кнопка в шапке панели, возвращает на `login`.

### Раздел «Сотрудники» (`view: 'team'`, только владелец)

- Таблица: имя, почта, роль (выпадающий список), статус одним словом: «Активен» / «Приглашён», действие «Отключить доступ» (с подтверждением Dialog).
- Форма «Пригласить сотрудника»: поле почты (проверка формата), выбор роли, кнопка «Отправить приглашение» → сотрудник добавляется первой строкой со статусом `invited`, баннер «Приглашение отправлено на … (демо)».
- Смена роли в списке применяется сразу, баннер «Роль изменена».
- Под таблицей 13px text-secondary: «Демо. В рабочей системе права проверяются на сервере, действия пишутся в журнал».

### Панель водоканала

Основной сценарий — планшет и компьютер от 768 px. На телефоне панель открывается без горизонтальной прокрутки страницы, но это не целевой сценарий.

| Ширина | Раскладка |
|---|---|
| ≥ 1200 px | полный вид; «Сотрудники» — таблица |
| ≥ 1100 px | «Опубликовать уведомление» справа от сводки (колонка 380 px) |
| < 1200 px | «Сотрудники» — карточки (имя и статус, почта, роль, действие); заголовок «Панель водоканала · сентябрь 2026» — отдельной строкой |
| < 1100 px | «Опубликовать уведомление» под таблицей на всю ширину |
| < 900 px | метрики 2×2, поля страницы 20 px |
| < 600 px | поля 12 px, метрики мельче, подпись «муниципальное унитарное предприятие» скрыта, подписи дней на диаграмме — выборочно, таблица показаний прокручивается внутри карточки (`min-width: 520px`), карточки сотрудников в один столбец, кнопки модальных окон на всю ширину |
| < 360 px | метрики в одну колонку |

Модальные окна: `width: 100%`, `max-width` 480 / 440 px, `max-height` по высоте экрана. Боковая панель абонента: `max-width: 520px`, на узких экранах на всю ширину. Таблицы — внутри горизонтально прокручиваемых обёрток `.adm-scroll`. Экран входа: карточка `max-width: 400px`, на телефоне поля 16 px. Раскладка сводки задаётся классом `overviewClass` (`has-side` / пусто) и CSS, а не вычисляемыми колонками.

## 11. Ограничения демо и открытые риски

- Не проверено на реальных устройствах (iOS Safari, Android Chrome): жест «назад», экранная клавиатура, безопасные зоны.
- Не проверен режим «Крупный текст» (×1.25) на экранах 320–360 px — требование «ничего не обрезает» (раздел 4) для узких экранов не подтверждено.
- `100dvh` не поддерживается Safari ниже 15.4 — нужен запасной `100vh`.
- В карточном виде сотрудников (< 1200 px) отключена подсветка новой строки после приглашения.
- Зависимость от CDN (unpkg): без интернета страницы не открываются; при недоступности unpkg демо не работает.
- Вход в панель — демо-режим без защиты (любой пароль), репозиторий публичный, данные вымышленные. Реальные данные абонентов и сотрудников в репозиторий не попадают никогда.
- В истории git публичного репозитория виден рабочий e-mail автора — решение о переписывании истории за владельцем.
